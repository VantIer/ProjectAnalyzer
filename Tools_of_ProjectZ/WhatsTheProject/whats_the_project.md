# WhatsTheProject - 项目导航 Skill

## 概述

WhatsTheProject 是一个 AI Agent Skill，用于指导大模型理解 ProjectAnalyzer 生成的文档体系，并根据用户需求精准定位对应的程序组件。其核心价值是**避免超大项目分析导致的会话上下文占用**——AI Agent 无需读取全部源码，只需查阅影子文档目录即可理解项目并定位代码。

---

## 一、文档体系说明

ProjectAnalyzer 对项目进行分析后，会生成一套多层次的说明文档。以下详细说明每种文档的结构、内容和用途。

### 1.1 analyse_report.md - 项目全局概览

**位置**: 项目根目录 / 影子目录根目录

**内容**: 整个项目的核心功能总结和流程逻辑描述

**用途**:
- 快速了解项目全貌
- 确定项目整体架构和核心模块
- 作为导航的起点

**何时读取**: 首次理解项目时，先读此文件获得全局视角

**读取策略**: 完整读取，该文件通常不超过 1000 字

### 1.2 {项目名}_scan_summary.md - 结构扫描总结

**位置**: 项目根目录 / 影子目录根目录

**内容**: 项目路径、目录总数、文件总数等结构化统计信息

**用途**:
- 了解项目规模
- 确定目录层级深度

**何时读取**: 需要了解项目规模时

**读取策略**: 快速浏览即可

### 1.3 model_{dirname}.md - 目录功能总结

**位置**: 对应目录下 / 影子目录对应位置

**内容**:
- 目录下所有组件的核心逻辑总结（不超过 1000 字）
- 目录对外暴露的接口或外部调用
- 目录的外部引用关系

**用途**:
- 理解某个目录/模块的功能
- 定位特定功能所在的目录
- 理解模块间的依赖关系

**何时读取**:
- 从 analyse_report 定位到某个模块后，读取该模块的 model 文件
- 需要理解某目录功能时

**读取策略**: 完整读取，每个文件不超过 1000 字

### 1.4 ana_{filename}.md - 文件功能详情

**位置**: 与源文件同目录 / 影子目录对应位置

**内容**:
- 文件功能一句话总结（不超过 500 字）
- 文件对外暴露的接口
- 文件的外部引用

**用途**:
- 了解单个源文件的功能细节
- 确定某个接口或函数在哪个文件中
- 理解文件级别的依赖关系

**何时读取**:
- 从 model 文件定位到具体文件后
- 需要修改或分析某个具体文件时

**读取策略**: 按需读取，仅读取目标文件的分析文档

## 二、导航策略

### 2.1 自顶向下查找（推荐）

从全局到局部，逐级缩小范围：

```
用户需求: "找到处理用户认证的代码"
    │
    ▼
Step 1: 读取 analyse_report.md
    → 发现 "认证模块负责用户登录和权限管理"
    → 定位到 auth 目录
    │
    ▼
Step 2: 读取 model_auth.md
    → 发现目录包含: login.py, token.py, session.py
    → login.py: 处理用户登录验证
    → token.py: 生成和验证 JWT Token
    → session.py: 管理用户会话状态
    │
    ▼
Step 3: 读取 ana_login.py.md (按需)
    → 获取 login.py 的详细接口和引用信息
    │
    ▼
Step 4: 定位到源码 src/auth/login.py → 进行编码操作
```

### 2.2 关键词搜索

当不确定功能属于哪个模块时：

1. 在影子文档目录中搜索关键词
2. 优先在 model_*.md 文件中搜索（覆盖范围适中）
3. 如需更精确，再搜索 ana_*.md 文件

### 2.3 引用追踪

通过接口引用关系定位关联组件：

1. 在 ana_*.md 中发现某个接口被外部引用
2. 沿引用链找到调用方
3. 在 model_*.md 中确认模块级依赖

## 三、上下文管理规则

### 3.1 核心原则：按需加载，最小读取

| 场景 | 读取范围 | 说明 |
|------|----------|------|
| 了解项目全貌 | analyse_report.md | 仅 1 个文件 |
| 定位功能模块 | report + 目标 model_*.md | 2 个文件 |
| 修改特定文件 | report + model + ana | 3 个文件 |
| 跨模块分析 | report + 多个 model | 2-5 个文件 |

### 3.2 读取优先级

1. **analyse_report.md** (最高优先级 - 全局视角)
2. **model_*.md** (中等优先级 - 模块视角)
3. **ana_*.md** (最低优先级 - 仅在需要细节时读取)

### 3.3 避免的读取行为

- 不要一次性读取所有 ana_*.md 文件
- 不要在仅需了解模块功能时读取文件级分析
- 不要读取 .log 日志文件（除非排查问题）
- 不要读取 .project_snapshot.json 或 .shadow_sync_state.json

## 四、工具调用指引

### 4.1 文档缺失时

**判断条件**: 影子目录为空或缺少 analyse_report.md

**操作**: 调用 ProjectAnalyzer 生成文档

```bash
project-analyzer <项目路径> --config <配置文件>
```

然后调用 ShadowCopyer 同步到影子目录：

```bash
shadow-copyer <项目路径> --config <配置文件>
```

### 4.2 代码变化时

**判断条件**: 用户告知代码有变化，或分析结果与实际代码不符

**操作**: 调用 ProjectAnalyzer 增量模式更新文档

```bash
project-analyzer <项目路径> --diff --config <配置文件>
```

然后调用 ShadowCopyer 同步更新：

```bash
shadow-copyer <项目路径> --config <配置文件>
```

### 4.3 文档不同步时

**判断条件**: 影子目录中的文档明显过时或不完整

**操作**: 调用 ShadowCopyer 重新同步

```bash
shadow-copyer <项目路径> --full --config <配置文件>
```

## 五、典型工作流

### 5.1 用户请求修改功能

```
1. 读取 analyse_report.md → 理解项目整体
2. 根据需求定位相关 model_*.md → 理解模块
3. 按需读取 ana_*.md → 理解具体文件
4. 定位源码文件 → 执行编码修改
5. 修改完成后 → 提醒用户运行 project-analyzer --diff 更新文档
```

### 5.2 用户请求理解项目

```
1. 读取 analyse_report.md → 项目全貌
2. 读取关键 model_*.md → 核心模块
3. 向用户总结项目架构和核心流程
```

### 5.3 用户请求定位 Bug

```
1. 读取 analyse_report.md → 确定可能相关的模块
2. 读取对应 model_*.md → 确定可能相关的文件
3. 读取对应 ana_*.md → 获取接口和引用信息
4. 定位源码 → 分析 Bug 原因
```

## 六、影子目录结构参考

影子目录与项目目录结构完全相同，但只包含说明文档：

```
{project}_shadow/
├── analyse_report.md              ← 从这里开始
├── {project}_scan_summary.md
├── {project}_shadow.log
├── sync_report.md                 ← ShadowCopyer 同步报告
├── src/
│   ├── ana_main.py.md             ← 文件分析
│   ├── ana_utils.py.md
│   ├── ana_config.py.md
│   └── model_src.md               ← 目录分析
├── tests/
│   ├── ana_test_main.py.md
│   └── model_tests.md
└── .shadow_sync_state.json        ← 同步状态（不需要读取）
```

## 七、注意事项

1. **始终从 analyse_report.md 开始**，不要直接跳到 ana_*.md
2. **优先读取 model_*.md**，它的信息密度最高（总结了整个目录）
3. **ana_*.md 是细节层**，仅在需要了解具体接口或进行编码时读取
4. **影子文档是只读参考**，不要修改影子目录中的文档
5. **如果文档与代码不符**，提醒用户运行 `project-analyzer --diff` 更新
6. **超大项目**（1000+ 文件）应严格控制读取量，单次对话最多读取 5 个 model 文件 + 3 个 ana 文件
